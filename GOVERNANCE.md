# Governance

PSIRTMap is a SolonGate project. SolonGate funds the work and the maintainers
listed in [docs/MAINTAINERS.md](docs/MAINTAINERS.md) make the day-to-day
engineering decisions.

## Decision-making

Maintainers decide project direction, what to build next, and how, by
consensus. In practice this means discussing the change in an issue or pull
request and proceeding once both maintainers agree; the [roadmap](ROADMAP.md)
reflects the current result of that process. A maintainer can merge a change
once it meets the requirements in [CONTRIBUTING.md](CONTRIBUTING.md) and has
at least one other maintainer's review, per the repository's branch
protection rules.

If the two maintainers cannot agree on a direction, the change does not move
forward until they do. There is no casting vote or external arbiter today;
this is workable because the maintainer group is small, and this document
will be updated if that stops being true.

## Access and roles

Who holds maintainer access, and what that access permits, is documented in
[docs/MAINTAINERS.md](docs/MAINTAINERS.md). Granting or revoking maintainer
access requires both existing maintainers to agree before the change is made.

## Security and conduct decisions

Vulnerability triage and disclosure timelines follow
[SECURITY.md](SECURITY.md). Either maintainer can acknowledge and triage a
report; coordinating the fix and disclosure is a joint decision when both
maintainers are reachable.

Code of Conduct reports and enforcement decisions follow
[CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

## Changing this document

This document describes how PSIRTMap is actually run today. As the
maintainer group or SolonGate's involvement changes, the maintainers will
update it to match, following the same consensus process described above.
